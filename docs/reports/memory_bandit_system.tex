\title{\textbf{Contextual-Bandit Memory for GigaEvo:\\
BD-Proximity Card Reputation, Credit Assignment, and EV Auctions}}
\author{GigaEvo / Claude}
\date{2026-06-24 \quad (branch \texttt{feat/phase0-use-attribution}, PR \#282)}

\begin{document}
\maketitle

\begin{abstract}
GigaEvo injects ``memory cards'' (distilled, reusable insights mined from prior
mutations) into the LLM mutation prompt. Before this work, which card to inject
was decided by a \emph{global}, context-free reputation: a card's whole-run
help-probability posterior and a cohort-adjusted median gain, identical no matter
which program was being mutated. This report documents the system shipped on
\code{feat/phase0-use-attribution} (PR \#282), which reframes injection as a
\emph{per-context contextual bandit}. The context is the mutated parent's
MAP-Elites cell under the run's live behavior-descriptor (BD) tessellation; the
arms are the candidate cards; the action is the budgeted subset injected; and the
reward is the \emph{base-relative} fitness gain of the resulting child, credited
only to the cards the mutator both received for its named base parent and declared
it applied. Each card maintains an in-cell Beta posterior
$\theta\!\sim\!\mathrm{Beta}(1+n_{\text{help}},\,1+n_{\text{harm}})$ and a value
(magnitude) equal to the median in-cell gain; the auction bids
$\theta_{\text{bid}}\!\times\!\text{magnitude}$ via Thompson sampling against a
no-card baseline arm, abstaining below an EV floor. The whole stack reuses the
engine's own tessellation through a single memoizing \code{\$\{ref:\}} resolver,
so the bandit reads exactly the cells the algorithm is searching, at near-zero
additional dependency. Every claim below is derived from the source on the branch;
the final section is a copy-pasteable run guide for every knob.
\end{abstract}

\section{Executive summary}

\paragraph{What changed.} Three commits land on top of \code{origin/main}:

\begin{enumerate}[leftmargin=2em,itemsep=2pt]
\item \textbf{\code{cf65847c} --- split \code{shortlist\_k} from \code{max\_cards}
+ \code{thompson\_ev} EV-bid auction.} Recall width (how many cards the selector
LLM may shortlist) is now distinct from the injection budget (how many cards
reach the mutator). Fusing them at $1$ had collapsed the candidate pool before
any ranker ran, making the auction, budgeter, and efficacy posteriors no-ops.
Adds \code{EVThompsonAuctioneer} (bids $\theta\!\times\!\text{magnitude}$, EV-floor
abstention) and \code{TopBidBudgeter} (ranks by realized bid). Promotes the
\code{read.selection}, \code{auction.run}, and \code{budget.cap} decisions to
\code{INFO}.
\item \textbf{\code{70d3fbba} --- contextual-bandit card reputation + GAM
fresh-context reorder + LLM IO audit trail.} Adds \code{DecisionContext} /
\code{ContextualGain}; freezes the base-parent snapshot at child birth;
stamps used-only base-relative \code{gain\_events} through the write pipeline;
and adds \code{BDProximityReputation} behind the \code{memory/reputation} seam,
which re-buckets each card's gain events into the query parent's current cell and
bids the in-cell $\theta\!\times\!\text{magnitude}$, delegating cold cells to an
absolute-progress fallback. Every router's LLM I/O is logged to
\code{<run\_dir>/llm\_io/<router>.jsonl}.
\item \textbf{\code{50d22f68} --- infra: remove a decommissioned server} (not
part of the memory system; mentioned for completeness).
\end{enumerate}

\paragraph{Why it matters.} A card that helps near one region of behavior space
and hurts near another previously carried a single blended reputation, so it was
either over-injected everywhere or under-injected everywhere. Partitioning the
card's evidence by the cell of the program being mutated lets the same stored
event list bid high where the card has helped and abstain where it has not ---
the defining property of a contextual bandit over a context-free one.

\section{Background: MAP-Elites and the memory-card lifecycle}

\paragraph{Programs, cells, behavior space.} GigaEvo evolves Python functions
under MAP-Elites. A \emph{behavior space} (\code{BehaviorSpace}) tessellates a
small vector of behavior descriptors into discrete \emph{cells}; each cell keeps
its elite (best-fitness) program. For the tabular substrate the descriptors are
\code{local\_lipschitz\_p95} $\times$ \code{ood\_delta\_slope} on a $15\times10$
grid (\code{config/algorithm/tabular/2d\_local\_ood.yaml}); the generic
single-island config (\code{config/algorithm/single\_island.yaml}) tessellates
on \code{\$\{primary\_key\}} alone. The space is \emph{dynamic}: bounds expand as
the search discovers new descriptor ranges, so a fixed program can change cells
between reindexes --- which is why the bandit never stores a cell id, only the
parent's metric vector.

\paragraph{Cards.} A memory card carries an \code{EvolutionStatistics} block.
The decision-relevant fields are the whole-run aggregate
\code{ALL: CardStatsBlock} (\code{posterior\_a}, \code{posterior\_b},
\code{intro\_events}, \code{IntroGain\_best\_median},
\code{IntroGain\_best\_adj\_median}) and, new on this branch,
\code{gain\_events: list[ContextualGain]} --- the use-attributed, base-relative
injection events that the BD-proximity reputation re-buckets per cell
(\code{gigaevo/memory/shared\_memory/models.py}).

\paragraph{Read / write split.} The \emph{write} side (the ideas tracker, a
post-step hook) mines completed programs into cards and stamps their statistics.
The \emph{read} side (\code{MemoryReadPipeline}) runs at each mutation:
\emph{retrieve $\to$ shortlist $\to$ auction $\to$ budget $\to$ render}. This
report concerns the read-side decision and the write-side credit-assignment that
feeds it.

\section{The RL / contextual-bandit formalism}

The mapping the code implements is a stateless (one-shot) contextual bandit:

\begin{itemize}[leftmargin=2em,itemsep=2pt]
\item \textbf{Context} $x$: the cell of the parent being mutated. Operationally
$x = \text{behavior\_space.get\_cell}(\text{parent\_metrics})$, where
\code{parent\_metrics} is \code{parents[0].metrics} captured into a
\code{DecisionContext} at read time (\code{read\_pipeline.py}, lines forming
\code{decision\_context}). Because the tessellation is held live (not a snapshot),
$x$ is re-derived every read under the engine's current bounds.
\item \textbf{Arms} $a$: the candidate cards surviving retrieval and shortlist
for this mutation (\code{AuctionCandidate} rows in \code{read\_pipeline.py}).
\item \textbf{Action}: the budgeted subset of arms injected, $\lvert
\text{action}\rvert \le \code{max\_cards}$. The auction emits an emergent
$0..N$ winner set and the budgeter caps it.
\item \textbf{Reward} $r$: the base-relative fitness gain of the child the
mutation produced, $r = \text{child} - \text{base}$ (sign-normalized; see
\S\ref{sec:credit}). One scalar per credited card per child.
\end{itemize}

\paragraph{Per-card in-cell posterior and value.} For a card with in-cell event
subset $E_x$ (events whose own context falls in the same cell as $x$), define

\[
n_{\text{harm}} = \bigl\lvert\{e \in E_x : e.\text{gain} < 0 \ \lor\ e.\text{invalid}\}\bigr\rvert,
\qquad
n_{\text{help}} = \lvert E_x\rvert - n_{\text{harm}},
\]
\[
\theta \;\sim\; \mathrm{Beta}\bigl(1 + n_{\text{help}},\ 1 + n_{\text{harm}}\bigr),
\qquad
\text{magnitude}(x) \;=\; \operatorname{median}_{e \in E_x,\ \neg e.\text{invalid}} e.\text{gain}.
\]

These are exactly \code{BDProximityReputation.card\_posterior} (returns
$(1+n_{\text{help}},\,1+n_{\text{harm}})$) and \code{card\_magnitude}. The harm
predicate is \code{e.gain < 0 or e.invalid} --- a strictly-negative gain or an
invalid child. The value head and the probability head agree on what ``invalid''
means: an invalid child is harm in $\theta$ and is \emph{excluded} from the
magnitude median (\code{median(e.gain for e in in\_cell if not e.invalid)}), so its
stamped $0.0$ cannot drag a proven-harmful card's median up toward non-negative.
An all-invalid in-cell history yields magnitude $0.0$ (the bid
$\theta\!\times\!0 = 0$ abstains under the default \code{ev\_floor}), not the
optimistic cold prior. The auction draws $\theta$ from this Beta and bids
$\theta\!\times\!\text{magnitude}$.

\paragraph{Why this approximates a full contextual bandit.} A general contextual
bandit (e.g.\ Vowpal Wabbit's \code{cb\_explore\_adf}) learns a parametric policy
$\pi_\phi(a\mid x)$ over featurized context--arm pairs with importance-weighted
regression and an exploration schedule (epsilon-greedy, bagging, or softmax). The
GigaEvo design replaces the learned featurizer with the algorithm's \emph{already
existing} tessellation: the context features are exactly the BD coordinates the
MAP-Elites engine bins on, the policy is a per-(cell, card) Beta--Bernoulli with
Thompson exploration, and the value head is the per-(cell, card) median gain. This
is a tabular, conjugate special case --- one independent posterior per occupied
(cell, card) pair --- so it carries no learned parameters, no training loop, and
no new dependency beyond SciPy's Beta sampler already used by the base auction.
It trades the cross-cell generalization a parametric model would give (a cold cell
learns nothing from neighboring cells) for exactness, reproducibility, and a
near-zero-code reuse of the live tessellation. Cold cells fall back to a
context-free arm (\S\ref{sec:value}) rather than guessing.

\section{Credit assignment (use-attribution, Phase 0)}
\label{sec:credit}

The bandit's reward channel is only as good as its credit assignment: which card
earned the child's gain. Phase 0 makes attribution \emph{use-attributed} and
\emph{base-relative}.

\paragraph{Base-parent snapshot, frozen at birth.} The mutator's structured
output (\code{MutationStructuredOutput}, \code{gigaevo/llm/agents/mutation.py})
gained two fields:
\begin{itemize}[leftmargin=2em,itemsep=1pt]
\item \code{base\_parent: int} --- the 1-based parent ``whose overall structure
this child keeps. Reward and context anchor to this parent.''
\item \code{card\_ids\_used: list[str]} --- ``Exact ids of memory cards/insights
you actually applied \ldots (verbatim; do not invent ids).''
\end{itemize}
At child birth, \code{generate\_one\_mutation} (\code{gigaevo/evolution/engine/
mutation.py}) calls \code{freeze\_base\_parent\_snapshot(parents, base\_parent)},
stamping onto the child: \code{base\_selected\_ids} (the cards that were selected
\emph{for that base parent}) and \code{base\_metrics} (the base parent's metric
dict). Freezing is required because a parent's own \code{selected\_ids} metadata
is overwritten on every \code{NO\_CACHE} requeue --- attribution must read the
child's stamp, never the parent's mutable current state.

\paragraph{Used-only, base-relative gain events.}
\code{compute\_contextual\_gains} (\code{injection\_posterior.py}) credits a card
to a child only on the intersection
\[
\text{credited} \;=\; \{\text{base\_selected\_ids}\} \ \cap\ \{\text{card\_ids\_used}\}.
\]
Cards selected for the \emph{other} parent (donors) and hallucinated ids earn
nothing. The reward is the base-relative delta with sign normalization:
\[
\text{gain} =
\begin{cases}
\text{fitness} - \text{base\_fitness} & \text{if } \texttt{higher\_is\_better}\\
\text{base\_fitness} - \text{fitness} & \text{otherwise}
\end{cases}
\]
so a minimization task (e.g.\ heilbron, where lower fitness is better) yields a
positive gain for genuine improvement. An \emph{invalid} child emits one forced
harm event (\code{gain=0.0, invalid=True}) per credited card; children with no
frozen baseline (\code{base\_fitness is None} or empty \code{base\_selected\_ids})
contribute nothing. \code{base\_fitness} is resolved at the write seam from the
frozen \code{base\_metrics} under the run's \code{fitness\_key}, honoring validity
and sentinel semantics (\code{ideas\_tracker.\_base\_fitness}).

\paragraph{Faithfulness gate.} \code{MutationAgent.\_citation\_integrity} counts
how many cited insights and card ids appear verbatim (whitespace-normalized
substring) in the rendered prompt. Per its own docstring this is \emph{purely
observational}: the counts land in child metadata, and \emph{nothing is gated on
them} --- the hard credit gate is the \code{base\_selected} $\cap$ \code{used}
intersection at the write path. The integrity counts are an audit signal for
detecting a mutator that cites cards it was never shown.

\paragraph{Data flow.} \code{mutator (base\_parent, card\_ids\_used)}
$\to$ \code{generate\_one\_mutation} freezes \code{base\_selected\_ids},
\code{base\_metrics} $\to$ ideas tracker builds \code{InjectionOutcome} rows
$\to$ \code{compute\_contextual\_gains} $\to$ per-card \code{gain\_events}
$\to$ stamped onto \code{EvolutionStatistics.gain\_events} via the write pipeline
$\to$ read by \code{BDProximityReputation} at the next mutation.

\section{BD-proximity reputation (Phase 1)}
\label{sec:bd}

\code{BDProximityReputation} (\code{gigaevo/memory/core/bd\_proximity.py})
subclasses \code{BetaBinomialReputation}: write-side aggregation (posterior, harm
predicate, scorer) is inherited unchanged; only the per-call read of
\code{card\_posterior} / \code{card\_magnitude} switches to the in-cell subset.

\paragraph{Re-bucketing.} \code{\_in\_cell(card, context)} computes the query
parent's cell \code{behavior\_space.get\_cell(context.parent\_metrics)}, then
keeps every stored event whose \emph{own} context falls in the same cell
(\code{get\_cell(event.context.parent\_metrics) == parent\_cell}). A card that
helped near cell $A$ and hurt near cell $B$ bids high in $A$ and (via the EV
floor) abstains in $B$ \emph{from the same stored list}. Any of: no context, no
events, an out-of-range parent metric (\code{KeyError}), or zero in-cell events
$\Rightarrow$ the method returns \code{None}.

\paragraph{Cold-cell delegation.} When \code{\_in\_cell} returns \code{None}, both
reads delegate byte-for-byte to \code{fallback}, which defaults to
\code{RewardWeightedReputation(reward=AbsoluteMedianReward())} --- the
absolute-progress arm of \S\ref{sec:value}. A parent cell with no in-cell evidence
therefore reproduces today's context-free numbers with no regression.

\paragraph{The single-shared-tessellation invariant.} The bandit must read the
\emph{same} mutating tessellation the engine searches. This is enforced through
the \code{\$\{ref:\}} memoizing resolver (\code{gigaevo/config/resolvers.py}):
the first \code{\$\{ref:behavior\_space\}} instantiates the node and \emph{writes
the instance back into the config tree}, so every later reference --- the island
configs \emph{and} \code{bd\_proximity.yaml}'s
\code{behavior\_space: \$\{ref:behavior\_space\}} --- resolves to the identical
live object. Because \code{DynamicBehaviorSpace} mutates its bounds in place, the
reputation sees cell moves the instant the engine does. (Contrast \code{\$\{...\}}
interpolation, which would re-instantiate a fresh, frozen copy.)

\section{Value functions and absolute fitness}
\label{sec:value}

The magnitude (value) channel is a swappable \code{RewardDefinition}
(\code{gigaevo/memory/core/reward.py}), the credit-assignment half of the AOS
\code{CreditAssignment $\circ$ OperatorSelection} decomposition:

\begin{itemize}[leftmargin=2em,itemsep=1pt]
\item \code{AdjustedMedianReward} (legacy default) returns
\code{IntroGain\_best\_adj\_median} --- the cohort-adjusted median gain. Reproduces
the prior \code{BetaBinomialReputation.card\_magnitude} exactly.
\item \code{AbsoluteMedianReward} returns \code{IntroGain\_best\_median} --- the
\emph{raw} child-minus-best-parent median. A card whose children never beat their
parent carries a non-positive magnitude.
\end{itemize}

\code{RewardWeightedReputation} is \code{BetaBinomialReputation} with its hardwired
magnitude replaced by a pluggable \code{RewardDefinition}; the
\code{absolute\_progress} arm is
\code{RewardWeightedReputation(reward=AbsoluteMedianReward())}, used both as the
standalone control reputation (\code{config/memory/reputation/
absolute\_progress.yaml}) and as the cold-cell fallback inside
\code{bd\_proximity.yaml}.

\paragraph{The \S L1 credit-assignment fix.} The signed absolute magnitude closes
a loophole: because the EV bid is $\theta\!\times\!\text{magnitude}$ and the
auctioneer's \code{ev\_floor} requires the bid to be strictly positive, a card with
a non-positive absolute median can clear the safety gate yet bid $\le 0$ and be
\emph{abstained on}. The system never bids up a card it expects to net-regress.
This is achieved with no change to \code{EVThompsonAuctioneer} or
\code{BetaBinomialReputation} --- only the magnitude definition.

\section{The auction}

\paragraph{Thompson safety gate.} Both auctioneers share the no-card abstain gate:
for each candidate draw $\theta\sim\mathrm{Beta}(\text{posterior\_a},
\text{posterior\_b})$ and a fresh $\text{base}\sim\mathrm{Beta}(\text{baseline\_
prior})$ (default $\mathrm{Beta}(3,3)$); the candidate passes iff $\theta >
\text{base}$. Draw order (gate then baseline, per candidate) is part of the
contract for seed-exact replay.

\paragraph{EV bid and floor.} \code{EVThompsonAuctioneer.run}
(\code{gigaevo/memory/core/auctioneer.py}) additionally draws, per candidate, a
bid $\theta_{\text{bid}}\sim\mathrm{Beta}(\text{posterior\_a},
\text{posterior\_b})$ and forms the realized bid $\theta_{\text{bid}}\times
\text{mag}$, where $\text{mag}$ is the card's magnitude or, when cold
(\code{magnitude is None}), the optimistic \code{prior\_magnitude} (default
$0.1$). A winner must pass the safety gate \emph{and} clear the reserve:
\[
\text{selected} \;=\; (\theta > \text{base}) \ \land\ (\theta_{\text{bid}}\times\text{mag} > \texttt{ev\_floor}).
\]
With \code{ev\_floor}$=0$ (default), the auction abstains on any non-positive
expected gain. Cold cards bid against the positive \code{prior\_magnitude} so the
floor never strands a fresh card. If every retrieved card is expected to hurt, the
auction injects nothing.

\paragraph{Budgeter.} \code{TopBidBudgeter} (\code{gigaevo/memory/core/
budgeter.py}) caps the emergent winner set to \code{max\_cards}, retaining the
strongest winners by realized EV bid (a missing bid sorts as $0.0$); within budget
auction order is preserved. Its sibling \code{TopThetaBudgeter} ranks by raw
$\theta$ instead and pairs with the non-EV \code{thompson} auction.

\paragraph{The shortlist\_k vs max\_cards pool-collapse fix.} The decisive bug fix
(\code{cf65847c}): the read pipeline now passes \code{shortlist\_k} (recall width)
to the selector LLM's request, while \code{max\_cards} is the downstream injection
budget the budgeter caps to (\code{read\_pipeline.\_select}, the
\code{build\_core\_request(\ldots, max\_cards=shortlist\_k)} call). When the two
were fused at $1$, the selector returned a single card, so the auction ranked one
candidate, the budgeter capped one to one, and every ranking key (Thompson draw,
EV bid, efficacy posterior) was a no-op --- the pool collapsed \emph{before} any
ranker could discriminate. Splitting them ($\code{shortlist\_k}=10$,
$\code{max\_cards}=1$ is the shipped recipe) hands the ranker a real pool of $10$
to choose $1$ from. The default \code{shortlist\_k=1} preserves the legacy collapse
for byte-identical baselines.

\section{Observability}

\paragraph{LLM I/O audit trail.} \code{PromptIODumpHandler}
(\code{gigaevo/llm/io\_dump.py}) is a LangChain \code{BaseCallbackHandler} that
records every router call --- exact messages sent, response text, token usage ---
as one JSON object per call into \code{<run\_dir>/llm\_io/<router>.jsonl}, mutex-
guarded for concurrent interleaving. It is env-gated on \code{GIGAEVO\_LLM\_IO\_
DUMP\_DIR}, which \code{run.py.\_maybe\_enable\_llm\_io\_dump} sets to
\code{<output\_dir>/llm\_io} \emph{before} \code{instantiate(cfg)} (so routers
pick it up at construction). The flag is \code{llm\_io\_dump} (default on); set
\code{llm\_io\_dump=false} to disable.

\paragraph{INFO decision logs.} The three critical memory decisions emit at
\code{INFO} (so they reach the log file, not just the always-on JSONL event
stream):
\begin{itemize}[leftmargin=2em,itemsep=1pt]
\item \code{read.selection} (\code{ReadPipeline}): candidate / fetched / auction-
winner / budgeted / selected ids, per-stage timing, the full bid slate, and an
\code{empty\_reason} (\code{shortlist\_empty}, \code{fetch\_empty},
\code{auction\_rejected}, \code{render\_empty}, \ldots).
\item \code{auction.run} (\code{Auction}): candidate count, winner ids, baseline
prior, and (for EV) \code{prior\_magnitude} / \code{ev\_floor}, plus per-bid
$\theta$, baseline $\theta$, magnitude, and realized bid.
\item \code{budget.cap} (\code{Budgeter}): kept vs dropped ids and the per-card
bid (or theta) used to rank.
\end{itemize}

\section{Limitations and future work}

\begin{itemize}[leftmargin=2em,itemsep=3pt]
\item \textbf{Donor-card signal discarded.} The credit gate is
\code{base\_selected\_ids} $\cap$ \code{card\_ids\_used}. A card selected for the
\emph{other} parent and genuinely applied (a donor) earns nothing. This is a
deliberate conservatism --- crediting donors would conflate the base-relative
baseline --- but it discards real signal in two-parent crossover.
\item \textbf{Cold-cell fallback is context-free.} An unoccupied (or thinly
populated) cell delegates to the absolute-progress reputation, i.e.\ the global
median. The tabular special case carries no cross-cell generalization, so a sparse
tessellation behaves like the old global popularity contest until evidence
accumulates per cell. A parametric contextual model would borrow strength from
neighboring cells; this design does not.
\item \textbf{Sign and validity in the in-cell harm predicate.} The harm predicate
\code{gain < 0 or invalid} treats any strictly-negative base-relative gain as harm;
it does not apply the noise-band / counterfactual adjustment that the write-side
\code{EfficacyScorer} uses for the \code{ALL} posterior. In-cell counts are
therefore noisier than the global posterior on tiny $E_x$.
\item \textbf{Phase 2 A/B pending.} The \code{bd\_proximity} vs
\code{absolute\_progress} comparison (the \code{launch\_ab.sh} four-arm run) is the
intended validation; this report documents the mechanism, not yet its measured
effect. Trajectory-shape and run-to-run variance should be established before
declaring the contextual arm a win.
\end{itemize}
