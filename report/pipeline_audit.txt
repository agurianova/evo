2. Как теперь читаются MaSIF (как вы просили)
---------------------------------------------
Файлы ImmRep25:
  masif/{cpx}/tcr.npz   orientation=straight  → TCR direct
  masif/{cpx}/pmhc.npz  orientation=flipped   → pMHC flipped

Компилятор НЕ смешивает ориентации:
  TCR  → ключ desc_straight (fallback: desc)
  pMHC → ключ desc_flipped  (fallback: desc)
Плюс готовый pooled (80-d) с той же стороны.

CREATE_SURFACE при выключенном MaSIF включает ОБА флага
(tcr_direct и pmhc_flipped) и дальше score() читает оба npz напрямую.

Патчевые метрики (cosine / dot / l2 / max_sim / mean_topk / count_above_thr)
считаются между subsample 64 точек TCR-direct и 64 точек pMHC-flipped.
  nn_radius  — маска по xyz и patch_radius_A
  nn_learned — kNN в пространстве дескрипторов (без отдельной обученной сети)


3. Как PDB / GAT / interaction / model.type входят в score()
------------------------------------------------------------
PDB: CA из pdb/{cpx}.pdb, граф knn/radius, pooling mean/attention,
     scope full_complex|interface.
Архитектура — дешёвый прокси, не обученный GNN:
  gat              softmax(-dist) по соседям
  mpnn             среднее
  egnn / se3_*     среднее + координатный вес / двухшаговый вес

interaction: product / abs_diff / bilinear / cross_attention по векторам
peptide / MHC / TCR, fusion concat | gated_sum | cross_attention.

model.type выбирает, какие блоки конкатенируются:
  mlp_features / multimodal_mlp  — все активные модальности
  masif_siamese / masif_patch_*  — только поверхность (+ interaction)
  pdb_gnn                        — только структура
  seq_dual / seq_cross           — только последовательность
  multimodal_gated / cross_attn  — гейт / attn между модальностями
  ensemble                       — среднее score() членов

Голова — LogisticRegression (успевает в timeout эволюции).
Скрытые слои Transformer/ESM/настоящий GAT не обучаются.


4. Логические ошибки пайплайна (мутация → validate → archive)
-------------------------------------------------------------
Шаг эволюции:

  parent.metadata["mutation_context"]
       → MutationSuggestionStage (LLM, max_insights=1)
       → PmhctcrMutationOperator.mutate_single
            parse insight #1 → map_operator → apply_operator(guided)
            иначе UCB1/scheduler
       → JSON child в program.code
       → ParseJsonProgram
       → validate.py: compile_genotype → fit(train) → score(val)
       → Macro-AUC0.1 + behavior (modality_mix, n_params)
       → MAP-Elites replacement
       → on_program_ingested → bandit reward

Найдено и исправлено:

  A. Compiler игнорировал не-sequence поля.
     Фикс: problems/pmhctcr/{assets,features,compiler}.py

  B. mutate_single перезаписывал genotype.meta.generation := program.iteration
     (счётчик движка, не глубина линии). Child.json получал generation=47
     после 47-го мутанта. Early/late пул scheduler путался с линией.
     Фикс: generation из JSON не трогаем; scheduler.select(run_step, parent).

  C. LLM OPERATOR=CHANGE_MODEL; masif_siamese при выключенном MaSIF
     менял type, а файлы не включались. used_modalities падал обратно
     на sequence, score() MaSIF не видел.
     Фикс: если insight просит masif, а флаги выключены → CREATE_SURFACE.

  D. Guided CHANGE_CALIBRATION всегда писал temperature=1.0 (no-op на сиде).
     Фикс: парсинг числа или отражение 4-T в [0.5, 3].
     Замечание: temperature по-прежнему не двигает AUC0.1 (монотонная
     калибровка; TZ это допускает).

  E. load_joined(root) брал parquet из того же root, что и 64 GiB assets.
     Фикс: таблицы всегда problems/pmhctcr/tables; npz/pdb из data_root().
     load_folds() кэшируется в процессе (validate в subprocess — кэш
     живёт на воркере exec_runner).

  F. Импорты compiler/features через problems.pmhctcr.* ломают
     CallValidatorFunction (в PYTHONPATH только problem dir).
     Фикс: try/except fallback на локальные импорты, как у validate.py.
