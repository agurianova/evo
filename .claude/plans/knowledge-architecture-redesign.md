# Knowledge Architecture Redesign

## Problem

GigaEvo's research knowledge is scattered across 7+ stores with ~40% content duplication:

| Store | What's in it | Problem |
|---|---|---|
| `experiments/INDEX.md` | Experiment ledger (status, verdict, PR) | Canonical — no issue |
| `experiments/<task>/CONTEXT.md` | Task knowledge, baselines, infra, bugs | Canonical — no issue |
| `experiments/<task>/<name>/05_results.md` | Detailed per-experiment results | Canonical — no issue |
| Elena's MEMORY.md (61 lines) | Experiment verdicts + methodology insights | **Duplicates INDEX.md verdicts** |
| Volkov's MEMORY.md (87 lines) | Design critiques + failure modes | **Overlaps with Hiroshi's failure modes** |
| Hiroshi's MEMORY.md (89 lines) | Protocol audit + failure modes | **Overlaps with Volkov's failure modes** |
| Retrospective's MEMORY.md (35 lines) | Cross-experiment patterns | **100% derivative from INDEX.md** |
| Literature Scout's MEMORY.md (4 lines) | Empty | Unused |

**Root cause**: Each agent independently accumulates its own view of shared facts. No single agent "owns" consolidation. AI Co-Scientist solves this with one shared Context Memory managed by a Supervisor; AI Scientist v2 solves it with a Journal class that generates summaries across all nodes.

---

## Design: Two-Tier + One Shared Pattern Store

### Tier 1: Canonical Sources (already exist, enhance)

These are the **read-only truth** that all agents consult. No agent duplicates their content in its own memory.

#### `experiments/INDEX.md` — Experiment Journal

**Current**: Flat table with (experiment, status, key_finding, PR).

**Enhanced**: Add structured metadata per experiment so agents can query without reading every 05_results.md:

```markdown
| Experiment | Status | Verdict | Effect (val) | Effect (test) | Treatment Type | Key Finding | PR |
|---|---|---|---|---|---|---|---|
| `hover/baseline` | Complete | POSITIVE | — | 51.65% (grand mean) | baseline | Cold-start baseline established | #90 |
| `hover/feedback_softfit` | Complete | POSITIVE | +3.42pp | +2.72pp | feedback+fitness | Soft fitness helps; feedback alone NULL | #92 |
| `hover/dynamic-topology` | Complete | POSITIVE | +5.16pp | +8.5pp vs GEPA | topology | Dynamic topology beats fixed + GEPA | #116 |
| `hover/memory` | Complete | NULL | +0.61pp | +1.47pp | memory | p=0.31, suggestive but underpowered | #161 |
```

New columns:
- **Verdict**: POSITIVE / NEGATIVE / NULL / SUGGESTIVE / INCONCLUSIVE / REGRESSIVE
- **Effect (val)**: pp delta on validation set
- **Effect (test)**: pp delta on test set (if has_test_set)
- **Treatment Type**: category tag (topology, feedback, fitness, memory, prompt, crossover, meta-evolution, infrastructure)

**Why**: This is what AI Scientist v2's Journal does — structured per-experiment summaries that let the next experiment's designer see patterns without reading 12 separate 05_results.md files. The retrospective-analyst reads this table instead of maintaining its own copy.

**Auto-generated by**: `/experiment-closeout` Step 8 (already exists, just needs schema update).

#### `experiments/<task>/CONTEXT.md` — Task Knowledge Base

**No schema change needed.** Already well-structured with:
- Part 1: Stable task knowledge (benchmarks, chain structure, dataset, variants, pipeline rules, known bugs)
- Part 2: Infrastructure (servers, endpoints, corpus)

**Enrichment** (already wired from this session's work):
- Literature Scout adds external baselines (Step 2a of literature-search skill)
- Closeout adds experiment results to benchmarks table (Step 13 of closeout skill)

### Tier 2: Agent Memories — Insights Only, No Facts

Agent memories store **interpretive insights and methodological patterns** that cannot be derived from Tier 1 sources. They do NOT store experiment results, verdicts, baselines, or infrastructure details.

#### What stays in agent memory

| Agent | Memory contains | Memory does NOT contain |
|---|---|---|
| **Elena** | Design methodology lessons (e.g., "feedback alone is insufficient — always pair with fitness function changes"), research direction rankings | Experiment verdicts, baseline numbers, task details |
| **Volkov** | Recurring design flaws to flag proactively (e.g., "check `include_in_prompts` as hidden IV"), critique calibration notes | Experiment results, statistical recommendations |
| **Hiroshi** | Protocol-level audit findings, systemic methodology gaps | Experiment-specific critiques (those go in 02_review.md) |

#### What gets deleted

| Agent | Action | Reason |
|---|---|---|
| **Retrospective Analyst** | Delete MEMORY.md entirely | 100% derivative from INDEX.md. The retrospective skill already reads INDEX.md + all 05_results.md directly. |
| **Literature Scout** | Delete MEMORY.md entirely | Search results are ephemeral — the output (literature_brief.md) is saved per-experiment. Cumulative knowledge goes into CONTEXT.md benchmarks table, not agent memory. |

#### What gets rewritten

**Elena's MEMORY.md** — strip experiment results ledger (lines 3-40), keep only:
- Methodology insights (confirmed findings about what intervention types work)
- Research direction preferences
- Design patterns learned

**Volkov's MEMORY.md** — strip experiment-specific critique history, keep only:
- Recurring failure modes to flag proactively (the "GigaEvo Failure Modes" section)
- Critique calibration patterns

**Hiroshi's MEMORY.md** — keep as-is (already protocol-focused, minimal duplication).

### Shared Pattern Store (NEW)

#### `experiments/PATTERNS.md` — Cross-Cutting Research Patterns

**Purpose**: The consolidated "what have we learned" across all experiments and tasks. This is what AI Co-Scientist's Meta-Review agent produces — a periodically updated synthesis.

**Schema**:

```markdown
# Research Patterns

Last updated: 2026-04-08 (after hover/memory closeout)

## Confirmed Patterns (strong evidence across 2+ experiments)

| Pattern | Evidence | Confidence | Tasks |
|---|---|---|---|
| Dynamic topology >> fixed topology | hover/dynamic-topology (+8.5pp), hover/7step-dynamic (+8.33pp test) | HIGH | HoVer |
| Prompt-level interventions fail consistently | hotpotqa/prompt_coevolution (NULL), hover/prompt_coevolution (NULL), hover/co-evolution-bus (REGRESSIVE) | HIGH | HoVer, HotpotQA |
| Soft fitness functions help modestly | hover/feedback_softfit (+2.72pp test) | MEDIUM | HoVer |

## Refuted Hypotheses (tried and failed)

| Hypothesis | Evidence | Tasks |
|---|---|---|
| Prompt co-evolution improves fitness | 3 NULL/REGRESSIVE results | HoVer, HotpotQA |
| Memory mechanisms improve retrieval | hover/memory NULL (p=0.31) | HoVer |

## GigaEvo Platform Failure Modes

| Failure Mode | Discovered In | Status | Impact |
|---|---|---|---|
| `include_in_prompts` as hidden IV | hover/dynamic-topology design review | ACTIVE — check every design | Confound: silently changes treatment |
| Pipeline/validate.py mismatch | hotpotqa/val_gap | FIXED | Corrupts mutation prompts |
| `model_name` config drift | hover/co-evolution-bus | ACTIVE | Silent fallback to wrong model |
| Stale workers repopulating Redis | Multiple | FIXED (flush.py) | Corrupts "clean" relaunch |

## Open Questions (highest information gain)

| Question | Why It Matters | Suggested Experiment |
|---|---|---|
| Does GAN-like D→G feedback improve construction? | Structured critique as mutation gradient | adversarial/heilbron-prover-v2 |
| Can topology + soft fitness stack? | Two strongest interventions untested together | hover/topology-softfit |
```

**Who writes**: Retrospective skill (Step 3 output goes here instead of RESEARCH_STRATEGY.md). Closeout adds new entries.

**Who reads**: Elena (before designing), Volkov (before reviewing), Literature Scout (for internal context).

## Knowledge Flow Diagram

```
                    WRITE                          READ
                    ─────                          ────

Closeout ──────────► INDEX.md ◄──────────────── Elena (design)
  (Step 8)           (experiment journal)         Volkov (review)
                                                  Retrospective skill
                                                  Literature Scout

Closeout ──────────► CONTEXT.md ◄────────────── Elena (design)
  (Step 13)          (task knowledge)             Volkov (review)
Literature Scout ──►                              All design-time agents
  (Step 2a)

Retrospective ─────► PATTERNS.md ◄────────────── Elena (design)
Closeout ──────────►  (cross-cutting insights)    Volkov (review)

Elena ─────────────► Elena's MEMORY.md           Elena only
  (methodology       (insights only,             (self-reference)
   insights only)     no facts)

Volkov ────────────► Volkov's MEMORY.md          Volkov only
  (failure modes      (patterns only,            (self-reference)
   only)              no results)
```

**Key principle**: Knowledge flows DOWN (from experiments into shared stores), then OUT (from shared stores into agent prompts). Agents never duplicate shared store content in their own memory.

## Migration Plan

### Step 1: Enhance INDEX.md schema

Add columns: Verdict, Effect (val), Effect (test), Treatment Type. Backfill from existing Key Finding text + 05_results.md files.

### Step 2: Create PATTERNS.md

Initialize from:
- Elena's confirmed findings (lines 47-55 of her current MEMORY.md)
- Volkov's failure modes (lines 56-86 of his current MEMORY.md)
- Retrospective analyst's cross-experiment patterns (lines 18-23 of its current MEMORY.md)

### Step 3: Rewrite Elena's MEMORY.md

Strip experiment results ledger. Keep only methodology insights (~10 lines).

### Step 4: Rewrite Volkov's MEMORY.md

Strip experiment-specific critique history. Keep only proactive failure mode patterns. Move platform failure modes to PATTERNS.md.

### Step 5: Delete retrospective-analyst and literature-scout MEMORY.md

These agents read canonical sources directly. No persistent memory needed.

### Step 6: Update agent prompts

Each agent's `.claude/agents/*.md` file gets updated "Memory" section:
- Elena: "Read `PATTERNS.md` + `CONTEXT.md` + `INDEX.md` before designing. Your MEMORY.md stores methodology insights only."
- Volkov: "Read `PATTERNS.md` before reviewing. Your MEMORY.md stores recurring design flaw patterns only."
- Retrospective: Remove memory section entirely. Skill reads INDEX.md + 05_results.md + PATTERNS.md.
- Literature Scout: Remove memory section entirely.

### Step 7: Update skills

- `/experiment-closeout` Step 8: Auto-generate INDEX.md row with enhanced schema
- `/experiment-closeout` Step 13a: Update PATTERNS.md (not agent memories)
- `/experiment-retrospective` Step 3: Write to PATTERNS.md (not RESEARCH_STRATEGY.md)
- `/experiment-design` Step 3 (Elena): "Read PATTERNS.md for cross-cutting insights"

### Step 8: Update main MEMORY.md

Remove "Active Experiments" table (duplicates INDEX.md). Remove "HoVer Baseline" (lives in CONTEXT.md). Keep only conversation-level memory.

## SOTA Justification

| Design Decision | SOTA Precedent |
|---|---|
| Single shared knowledge store (PATTERNS.md) | AI Co-Scientist: shared Context Memory managed by Supervisor |
| Structured experiment summaries in INDEX.md | AI Scientist v2: Journal class with per-node summaries |
| Agents read shared stores, don't duplicate | AI Co-Scientist: all 7 agents read from Context Memory |
| Consolidation at closeout/retrospective | AI Co-Scientist: Meta-Review agent periodic synthesis |
| No agent-specific experiment results | AIDE: Summarization Operator extracts from history, agents don't cache |
| Failure modes as shared knowledge | SciAgents: static knowledge graph read by all agents |
