TASK
Evolve a versioned JSON PredictorGraph for supervised tabular learning. The graph is feature-agnostic: it never names raw columns. A runtime type-aware encoder converts any assembled table into a numeric matrix, then a closed operator DAG predicts the target directly through a ridge or logistic readout. In synthetic mode the hidden GeneratorDAGs are frozen data sources, not genomes: only this PredictorGraph evolves. Each episode exposes (X_context, y_context, X_query), and the evaluator retains y_query until scoring. Real mode uses the existing tabular protocol; synthetic mode evaluates the same genome across a fixed meta-train task bank.

GENOME CONTRACT
The genome is one JSON PredictorGraph:
- schema_version: 1
- nodes: topologically ordered operator nodes; the neutral seed may contain no nodes
- readout: final ridge or logistic head over selected channels

Each node declares id, op, inputs, params, gate, is_readout, and rationale. The only reserved input name is "raw", which refers to the encoded table produced at runtime. Generated inputs must come from earlier node ids listed in inputs. gate in [0, 1] scales the node's readout channels before regularized fitting; gate=0 disables that node at readout. Every node must influence the final prediction: it must either set is_readout=true or feed a later node that does. A non-readout leaf is a dead node and is invalid.

Execution is topological, not a choice of one path. Every productive node is evaluated once for fit, validation, and query rows; all nodes marked is_readout are concatenated (plus raw channels when include_raw=true) before the final readout.

READOUT
readout.kind is ridge for regression and logistic for classification. include_raw=true concatenates encoded raw features into the readout matrix. alpha is the regularization penalty: Ridge uses alpha directly and logistic uses C=1/alpha. For every real CV fold or synthetic episode, the evaluator compares alpha/10, alpha, and 10*alpha on labeled validation/context rows before refitting on all labeled rows available to that fold or episode.

OPERATOR CATALOG
identity: pass parent channels unchanged.
standardize: z-score each parent channel using fit rows only.
quantile: rank/quantile transform fit on fit rows; params seed, n_quantiles, output_distribution.
affine_activation: TabPFN SCM core; linear mix of parents plus activation tanh|leaky_relu|elu|identity. params: fit=pca|supervised_ridge, n_components, alpha, activation, seed.
rbf_features: GP-style random Fourier features; params: n_components, lengthscale, seed.
pairwise_product: multiply selected parent column pairs; params: k, seed.
column_gate: keep top-k parent channels by cross-fitted target association; multiclass association is computed one-vs-rest. params: k, seed.

LEAKAGE AND ROBUSTNESS
Every operator fits state only on labeled fit rows. Supervised operators return cross-fitted features for fit rows and full-fit features for validation/query rows. A supervised operator cannot consume any supervised ancestor in schema v1, because such a chain would require nested cross-fitting. Query and validation rows never influence fitted state, and y_query is not part of the predictor call. All randomness must be seeded through params.seed or deterministic defaults so repeated execution reproduces identical outputs. Unknown parameter names and out-of-range dimensions invalidate the child instead of silently becoming no-ops.

SYNTHETIC FITNESS
The frozen bank contains 100 deterministic regression tasks from 10 generator families, split 60/20/20 into meta-train, meta-valid, and sealed meta-test with 6/2/2 tasks per family. Evolution uses only meta-train. For each task, alpha is selected using a deterministic validation subset carved from labeled context; the graph is then refit on all context rows and scored on query rows. Task score is query R2 clipped to [-1, 1]. Fitness is the mean task score within each family, then the equal mean across families. One complete task is the statistical unit. Optimize mean fitness and monitor the lower-tail diagnostic task_score_p10; do not specialize to a fixed width or one generator family.

SANDBOX CLASSIFICATION FITNESS
The restricted sandbox is a separate frozen bank of 100 classification tasks. Its hidden GeneratorDAG prior uses only linear, tree-rule, MLP, and mixed compositions with 2--8 productive composition blocks including the fixed class-logit head; raw feature sources are not counted. A tree block may contain multiple split rules and an MLP block multiple hidden units, so block count is a topology limit rather than an equal-compute measure across families. The controlled support is 256|512|1024 total rows, 4|8|16|24 features, categorical fractions 0|0.25|0.5, maximum categorical cardinality 2|4|8, and 2|3|5 classes. Every task exposes only (X_context, y_context, X_query), task type, and class count. The predictor returns K-class probabilities. Task score is 1 - model_query_log_loss / laplace_context_prior_query_log_loss, clipped to [-1, 1]. Zero matches a no-feature context-prior classifier and one is perfect. Fitness is averaged within generator family and then equally across families. Evolution uses only meta-train; meta-test requires explicit reporting opt-in.

SEARCH GUIDANCE
Start from the neutral raw-readout baseline and make one coherent mutation. Declare structural_intent: local_edit, extend_chain, compose_chain, or simplify_graph. Use extend_chain when a useful parent intermediate should gain another processing stage; the child must be deeper than the parent. Use compose_chain to create a new multi-stage path of depth at least 2. Graph size and depth are diagnostic descriptors, not objectives to minimize. Prefer composing genuine intermediates over duplicating the same raw-derived computation. Keep rationales short and never add depth solely for complexity.
